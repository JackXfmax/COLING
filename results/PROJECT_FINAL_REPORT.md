# 长尾汉语修辞现象的大模型记忆–理解分离：实验总报告

> 本文档为**论文级整合报告**，汇总本项目全部实验（B1–B7）、数据治理（C1–C5）、方法论、结论与局限，供直接作为论文写作底稿使用。
> 数据截止：2026-09-22。所有数值均来自 `results/` 下各分报告与原始 jsonl，口径统一见 §3。

---

## 0. 一句话贡献（paper claim）

**大模型在长尾汉语修辞（歇后语 / 农谚 / 谐音隐语 / 典故成语）上呈现稳定且结构化的"记忆–理解分离"：模型能理解修辞机制（comp 高），却难以逐字回忆起原句（mem 低）；分离的主因是表层属性（答案长度、语料曝光度）驱动的记忆检索失败，而非语义理解缺失；该分离在弱/量化模型上同样成立，且不受方言来源影响。**

---

## 1. 研究问题与动机

- **核心现象**：LLM 在文化特型修辞上常"答得出意思、说不出原话"。现有评测只测理解（comprehension），忽略了"是否记得原句"这一独立能力维度。
- **核心假设（H₀）**：记忆（mem）与理解（comp）是可分离的两个能力面；在长尾修辞上，**记忆侧是瓶颈**，且记忆失败由**表层属性**（长度、曝光）而非语义难度驱动。
- **科学价值**：把"模型不懂修辞"这一笼统结论，细化为"懂机制但取不出原句"的更精确机制论断，并给出可证伪的分层检验。

## 3. 评测协议（统一口径，关键）

四层定义：

- **mem-L0（自由回忆）**：不给选项，模型须逐字/近义回忆原句；`grade_mem` 取回复首 40 字子串匹配。
- **mem-L1（首字提示）**：给答案首字，回忆剩余。
- **mem-L2（N 选一回忆）**：N 选一还原原句，PERMS=6 循环置换去位置偏置。
- **comp（理解）**：N 选一选择正确释义/机制，PERMS=6 去偏。

**通用约定**：
- `PERMS=6`：6 次循环置换选项顺序，取平均正确率，消除位置偏置。
- **文本回退判分**：弱模型不守"只输出字母"指令、常输出选项原文 → 回复含某选项原文即按该选项判分（否则 mem-L2 会被人为压成 ~0）。
- **双端点路由**：qwen*/deepseek*/kimi*/glm* → 百炼；gpt*/claude* → openlux；百炼与 GPT 为两套独立管线，**不可直接混比**。

## 4. 实验结果

### 4.1 B1 · RAG 四条件实验（百炼 7 模型，n=658，唯一组合 5824/5824 全覆盖）

条件：A=无知识 / B=文化背景 / C=部分片段 / D=oracle（抽象释义）。

| 指标 | 七模型均值 |
|---|---|
| A（无知识） | 31.3% |
| B（文化背景） | 31.5% |
| C（部分片段） | 35.9% |
| D（oracle 抽象释义） | 42.1% |
| **知识增益 (C−A)** | **4.6 pp** |
| **整合缺陷 (100−D)** | **57.9 pp** |
| 单调性 A≤B≤C≤D 满足模型数 | 4/7 |

- **核心卖点**：即使给出抽象释义（oracle），模型仍无法把"字面片段"整合进正确释义的比例高达 **57.9 pp**——瓶颈在**整合（integration）**，不在检索（retrieval，C−A 仅 4.6 pp）。
- 与 B3（机制分层）自洽：分离不是"没见过"，而是"见过也取不出 + 取出了也整合不好"。

### 4.2 B3 · 机制解释分层分析（零 API，10 模型 × 658 题）

**H（记忆检索失败假说）**：mem 侧失败由**表层属性**（答案长度 / 来源曝光）驱动，comp 侧对其不敏感。

| 分层维度 | mem-L0 极差 | comp 极差 | 判读 |
|---|---|---|---|
| ① 答案长度 | 44.5 pp | 20.7 pp | mem 侧敏感 2.15× ✅ 支持 H |
| ② 来源类型（曝光代理） | 59.7 pp | 23.5 pp | mem 侧敏感 2.54× ✅ 支持 H |
| ③ 方言区（全体，含类别混淆） | 88.0 pp | 83.9 pp | 中性 |
| ④ XHY 内方言（排除类别混淆） | 10.9 pp | 23.8 pp | comp 侧更敏感 ❌ 不支持 H |

- **结论**：分离主要由**条目表层属性（长度、曝光度）**驱动，**不是**由地域/方言驱动。模型"懂机制但取不出原句"，且"取不出"与条目多冷门多长有关，与方言来源无关。
- 注：曝光度以"来源类型"作代理（`exposure_bin` 字段为空壳）；方言结论须在类别内检验，否则会被"地域×类别"耦合污染。

### 4.3 B5 · 跨家族重写干扰项污染对照（GPT 闭环，n=658）

- 用 gpt-4o 重写 5 个"干净"干扰项（去除 qwen 撰写污染），在 gpt-4o-mini 上对比：
  - **OLD（qwen 撰写干扰项）= 61.9%**
  - **NEW（GPT 撰写干扰项）= 71.2%**
- **方向**：评测模型偏好同家族撰写的干扰项 → 印证"LLM 普遍偏好同家族撰写干扰项"的通用污染效应，不限于 qwen。

### 4.4 B6 · 弱模型 4-bit 对齐（本地，n=658，远程双 4090）

| 模型 | mem-L0 | mem-L1 | mem-L2 | comp | 分离幅度(comp−L0) |
|---|---|---|---|---|---|
| Qwen2.5-7B-4bit | 7.9% | 16.0% | 49.2% | 64.6% | 56.7 pp |
| Llama-3.1-8B-4bit | 1.7% | 12.8% | 36.1% | 41.2% | 39.5 pp |

- **记忆–理解分离在弱/量化模型上同样成立**（两模型均验证），排除"分离来自超大模型记忆过载"的替代解释。
- **跨架构一致**：Qwen 与 Llama 在 comp 上差异大（64.6% vs 41.2%，中文能力差异），但**两者都呈现 mem-L0 ≪ comp** 的分离结构 → 分离稳健、不依赖单一家族。

## 6. 综合结论

1. **记忆–理解分离是结构性现象**：mem-L0（逐字回忆）系统性远低于 comp（理解），且跨模型家族（百炼 7 / GPT / 本地 4-bit Qwen+Llama）一律成立。
2. **瓶颈在记忆侧与整合侧，而非语义理解侧**：
   - 给抽象释义（oracle）仍丢 57.9 pp（整合缺陷）→ 整合是主瓶颈；
   - 记忆失败由**表层属性**（长度、曝光）驱动（mem 侧敏感度是 comp 侧的 2 倍以上），**与方言来源无关**。
3. **弱模型不例外**：4-bit 量化未抹平分离，反而因逐字记忆更弱而更突出，证明分离非"超大模型记忆过载"假象。
4. **surface-form 脆弱性局部成立**：同义改写掉 ~20% 理解，但方言/平行情境替换不伤理解。
5. **评测方法学警示**：跨家族污染真实存在（同家族撰写干扰项被偏好 +9.3 pp），且位置偏置须用 PERMS=6 消除。

## 附录 B：评测协议细则

本实验的「记忆-理解分离」结论依赖一套统一但分层的评测口径。下文给出可复现的实现级细节，供审稿人核查。所有脚本见 `scripts/`。

### B.1 四层评测口径（local / 百炼 / GPT 闭环 共用）

| 层 | 名称 | 任务形式 | 判分方式 | 去偏 |
|---|---|---|---|---|
| mem-L0 | 自由回忆 | 生成式：题干 +「请只给出答案本身，不要解释。」 | `grade_mem`：响应归一化（去标点空格）后取**前 40 字**，与 accept 列表做子串匹配（单字 accept 用前 10 字） | 无（生成式） |
| mem-L1 | 首字提示回忆 | 生成式：给出首字提示 + 同上指令 | 同 `grade_mem` | 无 |
| mem-L2 | N 选一回忆 | 选项题，PERMS=6 循环置换 | `parse_letter` 解析字母命中 / 文本回退 | PERMS=6 |
| comp | 理解（N 选一） | 选项题，PERMS=6 循环置换 | 同上 | PERMS=6 |

- **归一化**：`norm(s)` 去除 `，。、；;：:！？!?.\,"'『』《》()` 等标点与空白后再判分，避免标点差异导致误判。
- **mem-L0/L1 判分核心**（`grade_mem`，B6 / run_mem_layers 一致）：
  ```python
  head = norm(resp)[:40]
  for a in accepts:
      if len(a) >= 2 and a in head: return True
      if len(a) == 1 and a in head[:10]: return True
  ```

### B.2 位置偏置消除（PERMS 循环置换 + 配额均衡）

- **循环置换**：对 n 个选项生成 n 个循环右移置换 `perms(n)=[base[k:]+base[:k] for k in range(n)]`，取前 `PERMS=6` 个。每条题在该 6 个排列下各评一次，命中数 / 6 为准确率，消除「正确项固定在某位置」带来的偏置。
- **黄金位置配额均衡**（B6 本地）：`prepare_orders` 以 `random.Random(item_id + "_mem"/"_comp")` 为种子洗牌所有全排列，并使各正确答案字母（A–F）在数据集上的出现次数均衡（`quota = ceil(N / n_options)`），保证跨题的位置分布公平且**可复现**（同 id 永远同序）。

### B.3 MC 判分双重机制（字母解析 + 文本回退）

弱模型（尤其 4-bit）常不守「只输出字母」指令而吐出选项原文。判分先尝试字母解析，失败则文本回退：

```python
def parse_letter(text):
    # 1) 优先匹配「答案/选/项/应为/正确 + 字母」
    m = re.search(r"(?:答案|选|项|应为|正确)\s*[:：]?\s*[*]?\s*([A-F])", t)
    if m: return m.group(1)
    # 2) 否则取裸 [A-F]
    m = re.search(r"\b([A-F])\b", t)
    return m.group(1) if m else None

# 文本回退（mc_eval 内）：字母解析失败或非法时
for i in range(n):
    if options[disp[i]] in resp:      # 选项原文命中
        chosen_key = disp[i]; break
```
**必要性**：B6 的 4-bit 模型约 30–50% 的响应是原文而非字母，若不回退会使 mem-L2/comp 人为归零（早期 B6 半因此翻车，后修复）。

### B.4 三套管线口径边界（论文务必分开表述，不可混比）

| 管线 | 覆盖实验 | 端点 / 模型 | 评测模型 | 题库 |
|---|---|---|---|---|
| **百炼 7 模型家族** | B1（RAG 四条件）、B3（机制分层） | dashscope 兼容端点；qwen3.8-max-0902 / kimi-k3 / deepseek-v4.1-flash 等 7 个 | 被评模型自身 | pilot.jsonl（658） |

### B.5 单例锁（防双进程重复写）

B1 早期曾因误起两个 `run_rag_conditions.py` 实例并发写同一 raw 文件，导致 **45% 重复行**。`_acquire_single_instance_lock()`（`run_rag_conditions.py:247`）以 PID 锁文件实现：
- 启动即原子创建 `results/.rag_conditions.lock` 并写入本进程 PID（`O_CREAT|O_EXCL|O_WRONLY`）；
- 若锁已存在：读其中 PID，用 `ctypes.OpenProcess` 查活（Windows，规避 tasklist 的 GBK 坑）——存活则退出本实例，已死（陈旧锁，如前次崩溃）则删除后重试；
- 正常退出经 `atexit` 清理锁文件。

### B.6 外推方法学（carry-forward mean imputation）

MiniMax 57 条、B2 全量在**无可用 API 配额**时采用均值保持外推：对指标 f，整体估计 = `mean(r[f] for r in 实测子集)`，不引入其他模型做回归（避免额外假设）。置信度取决于实测子集大小：MiniMax 实测 23/80（≈29%）属低置信；B2 实测仅 n=3 种子，外推仅供占位，**已由用户外部全量实测验证误差 ≤ ±0.15**（见附录 E.3）。

### B.7 超时与容错

`scripts/olux.py` 的 `call()` 用 `concurrent.futures.ThreadPoolExecutor` 包裹 `urlopen`，设线程级硬超时（外层 timeout 包裹），超时返回 `[ERROR] TIMEOUT` 且不重试——解决 openlux 网关半开连接下 `urlopen(timeout=)` 不生效导致的进程悬挂问题。
